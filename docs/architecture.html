—DocScanner at a glance

A browser-based document scanner (like CamScanner, no watermark). 100% client-side — no backend, no accounts, no API keys. Scanned documents live in the browser's own IndexedDB. This page is fully offline; keep it with the repo.

1Runtime — everything in the browser

There is no server. React drives the UI; a single store wraps all state and IndexedDB writes; the imaging engine does every pixel operation on canvas. Heavy libraries are code-split and fetched only on first use.

2Build & deploy

A static Vite build (dist/) served over HTTPS by Cloudflare Pages. HTTPS is what lets the camera work on phones. Pushing to main is the whole deploy step.

Alternative path: a ready GitHub Actions workflow (.github/workflows/deploy.yml) deploys via Wrangler using repo secrets CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID. Use one path or the other — see §Account migration.

3Screen flow

One nav state in App.jsx (no router). A transient draft carries an in-progress scan through crop → filter. Re-editing a page reopens crop with the original image + stored corners, so edits are non-destructive.

4Scan → store → export pipeline

How an image becomes a stored page and then an export. Each page keeps its original + corners + filter for re-editing; processedImage is what you see and what gets composited with annotations at export.

5Auto-crop — tilt-aware corner detection

autoDetectCorners() is a self-validating cascade. It returns the first method that yields a plausible quad; a blob's corners are its diagonal extremes (min/max of x±y), giving a real tilted quadrilateral — not just an axis box.

Verified on synthetic scenes (real module, in-browser): tilted 18° light-on-dark, straight, dark-on-white, tilted 30° on colour — mean corner error ≤ 0.004 (normalised).

6Data model

Three IndexedDB stores. Images are base64 data URLs embedded in the records. Annotation positions are ratios (0–1) of the page's image rect, so they map correctly into any export size.

Top-level store record Embedded in a document Folder, Document, Signature are the three stores; Page & Annotation live inside Document.

7Module map

Components do UI; lib/ is framework-free logic (unit-testable in isolation); the store is the only thing that touches IndexedDB.

8Changing accounts (GitHub / Cloudflare)

Nothing in the code is account-bound and there are no secrets in the app, so a move is just: re-point the Git remote, then connect the new host. Full details in docs/ARCHITECTURE.md §10 and DEPLOY.md.
